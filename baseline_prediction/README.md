# Baseline Prediction Guide

This folder contains contributor-facing entrypoints for running memory-system
baselines on the Temporal Checkpoint Evaluation (TCE) protocol.

Use this README as the operational guide.

## Quick Start

TCE single run (recommended):
```bash
python -m baseline_prediction.run_tce --config configs/experiments/tce/<baseline>.yaml
```

TCE batch run:
```bash
python -m baseline_prediction.run_tce_batch --config <batch_config.yaml>
```

Dry-run config resolution (no execution):
```bash
python -m baseline_prediction.run_tce --config configs/experiments/tce/<baseline>.yaml --dry-run
```

## Output Layout

Expected generation output layout:

```text
baseline_prediction/
  <baseline_name>/
    results/
      <user_id>/
        prediction/
          *.json
        memory/   (optional)
        evaluation/     (auto-generated by evaluation)
```

Conventions:
- `<baseline_name>` must match evaluator baseline argument.
- `<user_id>` example: `003_user_003`.
- prediction JSON files are evaluator inputs.

## TCE Architecture

TCE uses a unified runner + config + adapter pattern.

Entrypoints:
- `baseline_prediction/run_tce.py`: single-run TCE entry
- `baseline_prediction/run_tce_batch.py`: batch TCE entry

Shared config layer:
- `baseline_prediction/tce_config.py`
- `configs/tce.default.yaml`
- `configs/experiments/tce/<baseline>.yaml`

Adapter layer:
- `baseline_prediction/adapters/base.py`
- `baseline_prediction/adapters/registry.py`
- `baseline_prediction/adapters/*.py`

Reproducibility artifact:
- each run writes `*_run_settings.yaml` next to prediction output.

## Add A New TCE Baseline

Minimal files:
- `baseline_prediction/adapters/<baseline>.py`
- `configs/experiments/tce/<baseline>.yaml`
- optional baseline-specific implementation folder under `baseline_prediction/<BaselineName>/`

Required adapter interface:
- implement `run(args: TceAdapterArgs) -> dict`
- import `TceAdapterArgs` from `baseline_prediction/adapters/base.py`
- register adapter in `baseline_prediction/adapters/registry.py`

`TceAdapterArgs` you should handle:
- `baseline`, `benchmark`, `app_logs_path`, `output`
- `llm_provider`, `llm_model`, `llm_max_workers`
- `max_visible_logs`, `resume`, `max_checkpoints`, `debug`, `debug_dir`, `save_prompt_and_raw`
- `extras` (from YAML `baseline_params`)

Expected adapter behavior:
- read benchmark and app logs
- run baseline generation
- write predictions to `args.output`
- return payload with `predictions` list (used by runner summary)

Registration example:
- add `"mybaseline": mybaseline.run` to `_ADAPTERS` in `baseline_prediction/adapters/registry.py`

TCE config example:
```yaml
runtime:
  baseline: mybaseline
  resume: false

data:
  benchmark: outputs/gemini_3_flash_preview/{user_id}/tce_benchmark.json
  app_logs_path: data/user{user_id}/app_log_large.json

output:
  prediction_path: baseline_prediction/mybaseline/results/{user_id}/prediction/tce_results.json

llm:
  provider: openai
  model: gpt-5-mini
  max_workers: 1

baseline_params:
  retrieval_top_k: 5
```

Validation checklist:
1. `python -m baseline_prediction.run_tce --config configs/experiments/tce/<baseline>.yaml --dry-run`
2. `python -m baseline_prediction.run_tce --config configs/experiments/tce/<baseline>.yaml`
3. `python -m evaluation.eval_tce --config configs/experiments/tce/<baseline>_eval_predict.yaml`
4. confirm `*_run_settings.yaml` exists next to prediction output

## Security Note

Do not create unignored backups of secret config files.
- avoid `.env.bak`-style files unless explicitly git-ignored
- prefer `.env.example` for templates without secrets
