# Generation Guide

This folder contains contributor-facing generation entrypoints for two protocols:
- DSP (dynamic state prediction)
- QA (question answering)
- TCE (temporal checkpoint evaluation)

Use this README as the operational guide.

## Quick Start

DSP single run (recommended):
```bash
python -m generation.run_dsp --config configs/experiments/dsp/<baseline>.yaml
```

DSP batch run:
```bash
python -m generation.run_dsp_batch --config <batch_config.yaml>
```

QA run (recommended):
```bash
python -m generation.run_qa --config configs/experiments/qa/<baseline>.yaml
```

QA bash wrappers:
```bash
bash generation/run_qa.sh --config configs/experiments/qa/oracle.yaml
bash generation/run_qa_batch.sh --config configs/experiments/qa/oracle.yaml
```

Dry-run config resolution (no execution):
```bash
python -m generation.run_dsp --config <config.yaml> --dry-run
python -m generation.run_qa --config configs/experiments/qa/<baseline>.yaml --dry-run
python -m generation.run_tce --config configs/experiments/tce/<baseline>.yaml --dry-run
```

## Output Layout

Expected generation output layout:

```text
generation/
  <baseline_name>/
    results/
      <user_id>/
        prediction/
          *.json
        memory/   (optional)
        eval/     (auto-generated by evaluation)
```

Conventions:
- `<baseline_name>` must match evaluator baseline argument.
- `<user_id>` example: `003_user_003`.
- prediction JSON files are evaluator inputs.

## DSP Architecture

DSP uses a unified runner + config + adapter pattern.

Entrypoints:
- `generation/run_dsp.py`: single-run DSP entry
- `generation/run_dsp_batch.py`: batch DSP entry

Shared config layer:
- `generation/dsp_config.py`
- `configs/dsp.default.yaml`
- `configs/experiments/dsp/<baseline>.yaml`

Adapter layer:
- `generation/adapters/base.py`
- `generation/adapters/registry.py`
- `generation/adapters/*.py`

Naming note:
- `generation/adapters/` is currently the DSP adapter namespace.
- Renaming to `generation/dsp_adapters/` is possible later, but not done now to preserve compatibility.

Reproducibility artifact:
- each run writes `*_run_settings.yaml` next to prediction output.

## Add A New DSP Baseline

Minimal files:
- `generation/adapters/<baseline>.py`
- `configs/experiments/dsp/<baseline>.yaml`
- optional baseline-specific implementation folder under `generation/<BaselineName>/`

Required adapter interface:
- implement `run(args: DspAdapterArgs) -> dict`
- import `DspAdapterArgs` from `generation/adapters/base.py`
- register adapter in `generation/adapters/registry.py`

`DspAdapterArgs` you should handle:
- `baseline`, `benchmark`, `app_logs_path`, `output`
- `llm_provider`, `llm_model`, `llm_max_workers`
- `max_visible_logs`, `resume`, `max_checkpoints`, `debug`, `debug_dir`, `save_prompt_and_raw`
- `extras` (from YAML `baseline_params`)

Expected adapter behavior:
- read benchmark and app logs
- run baseline generation
- write predictions to `args.output`
- return payload with `predictions` list (used by runner summary)

Registration example:
- add `"mybaseline": mybaseline.run` to `_ADAPTERS` in `generation/adapters/registry.py`

DSP config example:
```yaml
runtime:
  baseline: mybaseline
  resume: false

data:
  benchmark: data_construction/generated_outputs/gemini_3_flash_preview/{user_id}/dynamic_state_prediction_benchmark.json
  app_logs_path: data/user{user_id}/app_log_large.json

output:
  prediction_path: generation/mybaseline/results/{user_id}/prediction/dynamic_state_prediction_results.json

llm:
  provider: openai
  model: gpt-5-mini
  max_workers: 1

baseline_params:
  retrieval_top_k: 5
```

Validation checklist:
1. `python -m generation.run_dsp --config configs/experiments/dsp/<baseline>.yaml --dry-run`
2. `python -m generation.run_dsp --config configs/experiments/dsp/<baseline>.yaml`
3. `python -m eval.eval_dynamic_state_prediction --benchmark <...> --prediction <...> --output <...>`
4. confirm `*_run_settings.yaml` exists next to prediction output

## QA Architecture

QA uses a unified runner with a separate adapter namespace.

Entrypoint:
- `generation/run_qa.py`
- `generation/run_qa.sh` (shell wrapper)
- `generation/run_qa_batch.sh` (shell batch wrapper with user loop)

Shared config:
- `generation/qa_config.py`
- `configs/qa.default.yaml`
- `configs/experiments/qa/<baseline>.yaml`

QA adapter layer:
- `generation/qa_adapters/base.py`
- `generation/qa_adapters/registry.py`
- `generation/qa_adapters/*.py`

Current wired QA baselines:
- `qa_pipeline` (delegates to `python -m QA ...`)
- `oracle`
- `icl`
- `rag`

## Add A New QA Baseline

Minimal files:
- `generation/qa_adapters/<baseline>.py`
- `configs/experiments/qa/<baseline>.yaml`
- optional baseline-specific implementation folder under `generation/<BaselineName>/`

Required adapter interface:
- implement `run(args: QaAdapterArgs) -> dict`
- import `QaAdapterArgs` from `generation/qa_adapters/base.py`
- register baseline in `generation/qa_adapters/registry.py`

`QaAdapterArgs` you should handle:
- routing: `baseline`, `user_id`
- input/output roots: `input_root_dir`, `output_root_dir`, `qa_dir`, `output_path`
- model config: `llm_provider`, `llm_model`, `llm_max_workers`
- pipeline controls (for `qa_pipeline`): `command`, `subcommand`, `retry_times`, `flush_every`, `sample_per_group`, `sample_seed`, `qtypes`, `categories`, `fix_links_inplace`
- baseline params: `extras` (string map from YAML `baseline_params`)

Expected adapter behavior:
- run baseline generation command/module for one user
- write prediction JSON into `generation/<baseline>/results/<user_id>/prediction/`
- return a small payload (e.g. `{"command": [...], "returncode": 0}`)

Registration example:
- add `"myqa": myqa.run` to `_ADAPTERS` in `generation/qa_adapters/registry.py`

QA config example:
```yaml
runtime:
  baseline: myqa
  user_id: "001_user_001"

data:
  input_root_dir: /path/to/generated_outputs
  output_root_dir: /path/to/repo/generation/myqa/results
  qa_dir: /path/to/repo/generation/qa

llm:
  provider: openai
  model: gpt-5-mini
  max_workers: 4

baseline_params:
  log_size: large
  write_each: true
  resume: false
```

Validation checklist:
1. `python -m generation.run_qa --config configs/experiments/qa/<baseline>.yaml --dry-run`
2. `python -m generation.run_qa --config configs/experiments/qa/<baseline>.yaml`
3. `python -m eval.eval --mode batch --baselines <baseline> --users <user_id>`
4. confirm `qa_run_settings.yaml` exists next to prediction output

## Security Note

Do not create unignored backups of secret config files.
- avoid `.env.bak`-style files unless explicitly git-ignored
- prefer `.env.example` for templates without secrets
