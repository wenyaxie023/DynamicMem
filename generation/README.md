# Data Generation Output Format (Baselines)

This note is for baseline contributors. Please follow the directory layout below so evaluation can discover your outputs automatically.

## Required Directory Layout

```
generation/
  <baseline_name>/
    results/
      <user_id>/
        prediction/
          *.json
        memory/   (optional)
        eval/     (auto-generated by evaluation)
```

- `<baseline_name>`: Baseline name. Must match the name passed to `--baselines` during evaluation.
- `<user_id>`: User directory name, e.g., `003_user_003`.
- `prediction/*.json`: **Required**. The evaluator scans all `.json` files here and evaluates each one.
- `memory/`: Optional. Store intermediate memories or retrieval indices here.
- `eval/`: Created by the evaluator to store results.

## prediction JSON Format

Each `prediction/*.json` must be a **JSON array** with items like the following (extra fields are allowed):

```
[
  {
    "id": "...",           // optional
    "query": "...",        // required
    "reference": "...",    // required
    "prediction": "...",   // required [this is the answer predicted by the model]
    "predicted_evidence": [{...}] // list of dict [required]
    "metadata": {           // optional
    }
  }
]
```

## Dynamic State Prediction Artifacts

For dynamic state prediction baselines (paper terminology), use:

- Benchmark input:
  `data_construction/generated_outputs/gemini_3_flash_preview/<user_id>/dynamic_state_prediction_benchmark.json`
- Prediction output:
  `generation/<baseline>/results/<user_id>/prediction/dynamic_state_prediction_results.json`
  (RAG runner uses top-k-specific filenames such as
  `dynamic_state_prediction_results_topk5.json` / `dynamic_state_prediction_results_topk10.json`)

Dynamic state prediction generation notes:
- generation uses a shared LLM client implementation under `generation/common/llm_client.py`.
- openai/azure providers use structured response with per-checkpoint dynamic schemas.
- non-structured providers fall back to JSON-output prompting.
- openai/azure/aimlapi responses are requested with `truncation=\"auto\"` to reduce context-length failures.
